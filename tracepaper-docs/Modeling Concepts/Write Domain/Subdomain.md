## Overview
The concept of a **Subdomain** is technically nothing more than an organizational tool. Each behavior flow is deployed as its own runtime deployment using AWS Lambda, providing a technical boundary with an even smaller deployment granularity.

## Purpose
Subdomains serve as a **mental boundary**, offering a way to group related aggregates together. This grouping is purely organizational, represented as a directory name, and helps maintain clarity during the modeling process.

By grouping related aggregates into subdomains, you gain a better overview and structure without imposing any technical constraints or additional runtime configurations.
